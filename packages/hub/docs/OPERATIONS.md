# packages/hub — 運用の背景

## 認証機能

hub には職員ログイン機能が備わっており、未ログイン状態ではシステムにアクセスできない。住民情報の表示可能範囲は職員のロール・部署に基づいて制限され、許可されていない列はAPI・UI の双方から見えないようになっている。

### 初回セットアップ手順

オフラインサーバーへの初回導入時は、以下の順序で実行する必要がある。

**1. データベーススキーマの作成**

認証機能用の `users` テーブルを作成するため、`packages/hub/prisma/auth_init.sql` を実行する。

```bash
psql -U <user> -d <db> -f prisma/auth_init.sql
```

**2. SESSION_SECRET の設定**

`.env` ファイルに `SESSION_SECRET` を設定する。これはセッション（ログイン状態）の暗号化に使用される秘密鍵である。**32文字以上のランダム文字列**（英数字・記号を混在させることが望ましい）を生成して設定する。

```
SESSION_SECRET=<32文字以上のランダム文字列>
```

SESSION_SECRET は内部情報であり、**USB 上の `.env` ファイルに含まれるため、外部に漏洩させてはならない**。USB は施錠可能な場所に保管し、運搬時も厳格に管理すること。公開リポジトリに `.env` がコミットされることのないよう注意する（`.gitignore` に指定済み）。

**3. 職員アカウントの登録**

hub のディレクトリで、以下のコマンドを実行して職員アカウントを登録する。

```bash
node scripts/create-user.mjs <ログインID> <氏名> <部署> [role]
```

- `<ログインID>`: ログイン画面で使用するID（例: `yamada.taro`）
- `<氏名>`: 表示用の氏名
- `<部署>`: 部署名
- `[role]`: 権限レベル（省略時は `staff`、`admin` も指定可能）

実行すると、パスワード入力のプロンプトが表示される。**パスワードは画面にエコーされず、2回入力して確認される**（1回目と2回目が一致する必要がある）。

複数の職員アカウントを登録する場合は、このコマンドを職員ごとに繰り返す。

**4. hub サーバーの起動**

上記の準備が完了したら、通常通り hub を起動する。

```bash
npm start
```

起動後、ブラウザで `/login` 画面にアクセスでき、登録したログインID とパスワードでログインできることを確認する。

### 日常運用

#### 職員アカウントの登録・変更

新しい職員が配置されたときや権限が変わったときは、初回セットアップと同じコマンドで アカウントを登録する。

```bash
node scripts/create-user.mjs <ログインID> <氏名> <部署> [role]
```

#### 職員アカウントの無効化

離職や異動に伴い、アカウントを無効化する場合は以下のコマンドを実行する。

```bash
node scripts/disable-user.mjs <ログインID>
```

無効化されたアカウントではログインできなくなるが、**データベース上のレコードは削除されず、監査ログとして残る**。

#### セッション有効期限

ログイン後のセッション（ブラウザの Cookie に保存される JWT）は、**12時間有効**である。12時間以上経過してからアクセスした場合は、自動的にログイン画面にリダイレクトされる。

### セキュリティに関する注意

- **SESSION_SECRET は `packages/hub/.env` に記載されるため、内部情報として扱い、AI への入力や公開リポジトリへのコミットを避けること。**本番環境設定ファイル一式として、USB での物理運搬のみで対応する。
- **ユーザー登録・無効化コマンドはオフラインサーバー上で実行する必要があり、リモートアクセスやWi-Fi 経由の実行は許可されない。**
- 表示可能な列（データ項目）は `packages/hub/lib/permissions.ts`（実効的な閲覧範囲の計算）と `packages/hub/lib/permissionGroups.ts`（権限グループの定義）で制御されており、権限グループの割り当てにない列はAPI・UI から見えない。これにより、職員が誤って住民情報の全項目にアクセスすることを防いでいる。権限の付与・例外の設定は管理画面（`/admin/users`）から行う。
- 認証機能に使用している依存ライブラリ（`bcryptjs` と `jose`）は純 JavaScript 実装のため、ネイティブビルド・OS 依存パッケージは不要である。
